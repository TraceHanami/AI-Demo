Threat Modeling: OWASP Top 10 for LLM Applications

This demonstration environment illustrates the vulnerability mechanics and defensive architectural mitigations for two critical categories in AI application security.

OWASP LLM06

Excessive Agency

Definition: Occurs when an LLM-based agent is granted excessive functionality, excessive permissions, or excessive autonomy to execute actions without verification.

1. Excessive Functionality: Providing unnecessary tools (e.g. raw SQL query execution, shell maintenance scripts) to a customer support agent.
2. Excessive Permissions: Tool tokens holding full read/write database access rather than constrained user-scoped tokens.
3. Excessive Autonomy: Allowing high-impact actions (e.g. issuing large refunds, password resets) without human verification.

Defensive Mitigations Implemented:

  • Tool Allowlists: Exclude dangerous diagnostic tools from non-admin personas.
  • Role-Based Access Control (RBAC): Enforce permission checks before invoking any function.
  • Resource Ownership Validation: Invalidate Insecure Direct Object References (IDOR).
  • Human-in-the-Loop (HITL): Require supervisor dual-control sign-off for operations exceeding thresholds.
OWASP LLM04

Unbounded Consumption / Model DoS

Definition: Occurs when an LLM application accepts unrestricted request volumes, unlimited token lengths, or unbounded processing times, leading to financial exhaustion or service denial.

1. Request Floods: High-frequency automated attacks overwhelming LLM inference endpoints.
2. Token Exhaustion (Payload Bloat): Large payloads inflating context windows and depleting token budgets.
3. Computational Deadlocks: Recursive or hanging queries consuming server execution capacity.

Defensive Mitigations Implemented:

  • Sliding-Window Rate Limiting: Enforce 5 req/min cap with HTTP 429 Too Many Requests.
  • Session Request Quotas: Cap total queries per session (10 requests/session).
  • Token Budget Guardian: Enforce strict per-request (800 tokens) and session ceilings.
  • Circuit Breaker Pattern: Automatically trip into OPEN state under sustained attacks, fast-failing requests in <1ms.
  • Execution Timeout Controls: Kill hanging processes after 2.5 seconds.
